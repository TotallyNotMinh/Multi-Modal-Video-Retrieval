Here's the full list, in priority order:

## 1. Swap dense visual channel from CLIP ViT-B/32 → SigLIP
Highest-leverage, near-free change since you already have SigLIP embeddings cached from the keyframe pipeline. Re-run the benchmark on this first before anything else.

## 2. Route `visual_entity_text_grounded` queries to OCR first, not CLIP/SigLIP
This category (39% of the visual benchmark) scores worst under pure visual search because CLIP-family models are weak at reading on-screen text. You already have a PaddleOCR + BM25 index — send these queries there primarily, with dense visual as a secondary signal, instead of blending at a fixed global weight.

## 3. Per-category fusion weighting instead of one global config
Your own category table shows `DIRECT_INFO`/`NUMERIC_TEMPORAL` peak at ASR-heavy (0.30/0.70) while `visual_compositional_objects` peaks at baseline (0.70/0.30) — opposite optima. Add a lightweight query-type classifier (heuristic or cheap LLM call) before retrieval to pick weights per detected category, using the taxonomy you've already built.

## 4. Fix the NMS / ground-truth tolerance mismatch
Temporal NMS runs at ±2.0s but visual benchmark ground truth snaps at ±1.5s. Audit whether NMS is silently suppressing keyframes that fall within its own radius but outside GT tolerance — could be costing recall on borderline cases for free.

## 5. Standing translation quality eval
The SSE parsing bug caused a +182% relative recall jump once fixed — translation quality was silently capping performance. Build a small regression test (even ~50 hand-checked Vietnamese→English pairs) so a future plumbing bug doesn't go unnoticed for as long.

## 6. Fine-tune SigLIP (fallback, only if #1 doesn't fix saturation)
Targets the intra-corpus collision problem (e.g. *Món Ngon Mỗi Ngày*'s 500+ near-duplicate cooking videos scoring 0.32–0.38 cosine against each other) that a stronger base encoder alone may not solve.
- LoRA/adapter fine-tune, not full fine-tune — protects the general embedding space for other query categories.
- Hard negative mining is the actual work: cluster by show/series or by high-cosine (>0.85) non-duplicate pairs within your existing 177K matrix, rather than random in-batch negatives.
- Exploit SigLIP's sigmoid pairwise loss to weight hard-negative pairs asymmetrically, easier than restructuring batches for InfoNCE.
- Hold out a slice of your 800-query benchmark untouched as a regression check against forgetting.

Separately, from the earlier pipeline-quality pass (decoding/preprocessing side, not retrieval):

## 7. Scene-change filtering on top of NONKEY keyframe extraction
Pure I-frame sampling can over- or under-sample depending on GOP length; add histogram/SSIM-based dedup and gap-filling for long silent stretches.

## 8. Confirm resize + normalization exactly matches the SigLIP checkpoint's `preprocessor_config.json`
Aspect-ratio handling and the `(x/127.5) - 1.0` normalization formula need to match the specific checkpoint — a mismatch here degrades quality silently, no errors thrown.

## 9. Log which decode path (PyAV vs OpenCV fallback) was used per `video_id`
The two paths have very different sampling densities (NONKEY vs fixed 1.5s interval), which can bias downstream retrieval if left unaudited.

## 10. Cache "safe batch size" per GPU/resolution instead of re-discovering it via OOM every video
Avoids repeatedly re-triggering the same OOM-retry cascade on similar videos.

## 11. Store model checkpoint version/hash in the metadata JSON
Prevents silently mixing embeddings from different SigLIP versions in the same cache directory if you ever swap checkpoints (relevant now that you're switching encoders).
